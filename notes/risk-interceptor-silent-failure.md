# 风控拦截器在序列帧场景下的静默失效

**类型**：缺陷记录 · 内容安全 / 风控
**涉及模块**：风控拦截器（AOP 切面，统一挂在 Controller 上处理）
**关键词**：字段名约定、序列帧、prompt 拼装时机、静默失效、零报错

## 问题描述

原来的风控拦截器（AOP 切面，挂在 controller 上统一处理）按约定只认请求体里固定名字的字段：文字读 `prompt`，参考图读 `firstImageFileKey` 这类字段。序列帧场景里，前端提交的是主体、动作、色调等多个字段，完整的 prompt 要到 service 里才拼出来。拦截器运行时既没有 `prompt` 字段，也还没有拼好的 prompt，于是只能上报空内容，风控没有可命中的内容只能放行，等于没审，而且没有任何报错，属于静默失效。

## 关键点拆解

- **输入契约是隐式的**：拦截器依赖请求体里固定字段名（`prompt`、`firstImageFileKey` 等），而不是依赖「待审内容」这个语义本身。
- **拼装时机错位**：序列帧场景由前端提交主体、动作、色调等多个独立字段，完整 prompt 在 service 层才生成，Controller 层的切面天然看不到它。
- **降级路径无声**：拿不到内容时拦截器上报空内容，风控侧无内容可命中只能放行，链路全程不报错。
- **风险后果**：该场景实际处于未审核状态，且因为没有任何异常信号，从监控与日志上都难以被发现。

## 影响范围

- 序列帧（多字段提交、prompt 后置拼装）相关链路的内容审核整体失效。
- 同构风险：任何「请求体字段与审核所需内容不一致」的接口都会落入同一模式，而不只是序列帧一个场景。

## 待确认 / 后续方向

- 拦截器应改为面向「最终待审内容」取值，而非面向固定字段名。
- 拼装时机需要前移，或由 service 层显式回传拼装结果供审核使用。
- 取不到内容时不应静默放行，应作为显式异常或降级告警暴露出来。
